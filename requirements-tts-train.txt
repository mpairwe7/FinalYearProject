# Coqui TTS training toolchain — NOT part of the runtime environment.
#
# Split out of the root requirements.txt on 2026-09-03. Coqui `TTS` 0.22.0
# requires pandas>=1.4,<2.0, while the root requirements and
# App/backend/requirements.txt both require pandas>=3.0.5 (dependabot #416,
# #422). Those cannot be satisfied together, and because the TTS pin carried a
# `python_version < "3.12"` marker while CI runs 3.11, the marker was always
# true there: every install of requirements.txt on CI became unsatisfiable and
# the whole ML Pipeline job failed before running a single test.
#
# Coqui TTS is imported in exactly one place — ml/scripts/tts/train_luganda_vits.py
# — lazily, inside a try/except ImportError that already returns a structured
# error. Nothing at serving time touches it: the production Luganda voice path
# is Spark-TTS-SALT (see docs/runbooks/salt-speech-backends.md). Holding the
# entire runtime environment on pandas 1.x for one offline training script is
# the wrong trade, so it gets its own environment.
#
# This mirrors requirements-onnx-export.txt, split out for the same class of
# conflict (optimum[onnxruntime] vs transformers 5.x).
#
# Usage — install into a DEDICATED virtualenv, never the runtime one, or you
# will downgrade pandas underneath everything else:
#
#   python -m venv .venv-tts-train
#   .venv-tts-train/bin/pip install -r requirements-tts-train.txt
#   .venv-tts-train/bin/python ml/scripts/tts/train_luganda_vits.py ...
#
# Needs Python < 3.12: Coqui TTS 0.22.0 publishes no wheel for 3.12+.

TTS==0.22.0; python_version < '3.12'
trainer>=0.0.36; python_version < '3.12'
pandas>=1.4,<2.0; python_version < '3.12'
